# Planning: one bounded raw-email operator cycle

**Status:** DRAFT — independent Planning review requested; no execution evidence claimed  
**Version:** 1.0  
**Last Updated:** 2026-10-22

## Purpose

Translate the reviewed Design into one small executable operator cycle with explicit evidence and stop conditions. No schema, real transfer or mail import occurs in Planning.

## Scope In

The exact fixed sample, existing private PostgreSQL instance, Design record/transfer contracts, complete source preservation and the owner-requested bounded operator verification.

## Scope Out

Reusable application code, frameworks, new packages or app quality bindings, broader mailbox discovery/mutation, external AI, database recreation, UI, PR/merge/closure.

## Summary

One cycle, C_1, owns D_1.1 through D_1.5. Preserve the reviewed bytea/operator design and source/derivation/correction separation. All private receipts, originals, identifiers, paths and diagnostics remain outside repository/workflow artifacts. Only public-safe aggregate evidence and native lifecycle records are committed. Stored plan and this document use the same C_1/D_1.1–D_1.5 ordering and descriptions; phase-local D_1/D_2 references remain scoped to their named phase. File-existence validators are navigation checks, not proof of source fidelity. Operational obligations below require actual observed outcomes.

## Dependencies

- Independent exact-revision Planning GO and Co assignment are required before Implementation; first cycle entry is C_1.
- Use the worktree's exact admitted connection and sole mutation interval. Preserve the existing dedicated instance, credentials, private selection manifest and current source scope.
- Within C_1, D_1.1 raw receipt/storage precedes D_1.2 completeness and D_1.3 processing/reimport; D_1.4 relies on durable raw/processing state; D_1.5 reports all preceding evidence. Negative acquisition checks may use explicitly synthetic controls before real transfer.
- Full repository_review and native configured test request belong once in Validation after final implementation changes; retain fresh evidence unless invalidated.

## Milestones

- Planning snapshot and native stored C_1/D_1.1–D_1.5 mapping reviewed before real implementation.
- C_1 producer evidence and clean quiescent revision independently reviewed before final cycle/Implementation exit.
- Validation reviews factual operator outcomes plus branch gates and neutral configured-test result; Documentation preserves achieved scope and retrieval limitations.

## Work Units

**Goal:** Durably preserve the full selected mail sample and prove the stated invariants using bounded operator commands, without building an application service.

**Cycle Number:** 1

**Owner:** @imp implementer

#### Scope Out

#### Exit Criteria

All D_1.1–D_1.5 obligations have factual evidence: exactly eight real messages across three observed threads; untruncated received source and reconciled embedded originals; storage/export byte equality; unchanged real source/version counts after repeat import and reprocessing; traceable provisional derivations; demonstrated negative/failure/resume/correction protection; synthetic totals separate. Public evidence is screened, required narrow Markdown gates pass, private archive retained and dedicated server/clients/pipe stopped. Final C_1 exit and Implementation phase exit require independent exact-revision GO; producer results alone are not GO. Any incomplete source blocks a full-import statement and successful cycle exit.

#### Dependencies

- D_1.1: verify instance/manifest and safe transfer; source bytes/observation commit independent of later parser outcomes.
- D_1.2: reconcile the retained raw response's existing payload first; obtain an additional full read only if evidence is missing, and a separate attachment only if required and supported.
- D_1.3: derive from preserved bytes and reimport the identical fixed receipt; changed interpretation never changes source version.
- D_1.4: use explicitly isolated synthetic records for destructive/conflict/correction controls; recover all real archived bytes with connector acquisition disabled.
- D_1.5: compose screened implementation-evidence.md, perform narrow Markdown checks, commit/push only public-safe artifacts, quiesce and request independent final-cycle review.

#### Obligations

- Apply Research's approved additive/private/full-source/no-mailbox-change strategy and all Design contracts without weakening an acceptance criterion.
- No private values in shell argv, console output or public artifacts. Real payload transfer uses the framed CurrentUserOnly/FirstPipeInstance pipe into an approved private receipt, with byte length, SHA-256, exact identity-set and timeout/size-limit verification.
- Source and original provider envelopes are preserved even when parsing/charset/processor output fails; incomplete acquisition is classified and cannot be labelled fully imported.
- Operator/smoke evidence covers public behavioral invariants. No artificial RED/GREEN application-test cycle or new native test bindings is introduced for these transient operations; meaningful negative controls remain mandatory.
- No test correction is represented as an actual owner-accepted mail fact. Synthetic sources/versions/runs are counted separately from real eight-message totals.
- Final C_1 and Implementation phase exits require independent QA GO at the committed revision; no self-approval or automatic next phase.

#### Verification

##### D\_1.1 — identity and framed transport

**Method:** Verify dedicated database identity/configuration and private manifest; reject unknown existing schema/data. Transfer only the fixed eight complete responses with frame length/digest and private receipt read-back. Exercise synthetic bad-digest/truncated-frame and wrong-selection cases without accepting their payload.

**Expected Result:** Eight unique selected message identities; positive frame and persisted receipt bytes agree. Invalid/truncated/mismatched frames leave explicit rejected/incomplete evidence and never feed successful import. No private console output.

##### D\_1.1/D\_1.2 — complete original source

**Method:** Strictly decode raw base64url without newline/charset changes; check complete structured response for errors/truncation. Privately compare source lengths/digests and byte equality against committed raw bytea. Verify three actual provider threads.

**Expected Result:** Eight real preserved candidates with separately retained provider snapshots; exactly three observed threads. Any missing/unrecognized/truncated response is visible and prevents a full-import claim; do not substitute reconstructed text.

##### D\_1.2 — MIME/inline/attachment reconciliation

**Method:** Inventory nested MIME parts/headers/defects from raw; reconcile raw response payload fields before optional targeted full reads. Compare available part sizes and original decoded bytes; obtain only required supported originals missing from raw. Exercise a synthetic missing-part/unsupported classification.

**Expected Result:** Every inline/attachment-bearing part has an unambiguous original-content outcome. Required supplementary bytes are archived and checked, or completeness remains explicitly blocked. External linked targets stay unarchived; parser/charset limitations are separate.

##### D\_1.3 — provenance and duplicate prevention

**Method:** Store MIME inventory, extracted text, reply evidence and provisional context linked to source version plus processor/config version. Repeat the identical receipt and reprocess a changed proposal/version; compare before/after real source/version counts and bytes.

**Expected Result:** Eight real source identities and unchanged source-version counts on identical reimport or interpretation-only change; source hashes/bytes unchanged. Reply ambiguity remains unresolved; new proposals retain provenance and do not become accepted facts.

##### D\_1.4 — source conflict and correction protection

**Method:** Use a separate synthetic scope to supply changed bytes for one test provider identity and to reprocess after a test-labelled correction. Compare original source/correction rows byte-for-byte before/after and inspect conflict/proposal status.

**Expected Result:** Conflicting candidate retained and flagged; prior verified source unchanged. Correction retained, altered proposal separate, no false owner acceptance. Synthetic controls are excluded from real counts.

##### D\_1.4 — interrupted/failed/unsupported processing and resume

**Method:** Create a controlled processing interruption after durable source commit, leave a recoverable running attempt, reconcile to interrupted and resume missing work. Exercise a bounded unsupported/failed processor case and retain diagnostics privately.

**Expected Result:** Durable originals survive, failure/interruption is visible and resumable, successful work is not duplicated and original eight-source totals do not grow. Unsupported extraction cannot erase registration/raw storage.

##### D\_1.4 — archive-only recovery

**Method:** Disable connector acquisition for retrieval; export each real raw message and provider observation from PostgreSQL to the private root. Compare every recovered raw byte sequence with its retained acquisition receipt; compare supplementary originals where present.

**Expected Result:** Eight of eight recovered with length/SHA-256 and byte-for-byte equality, no source-content fetch from Gmail and no recovery dependency on derivations/search. Report missing exports or mismatches as failures.

##### D\_1.5 — evidence and quiescence

**Method:** Record the executed operator scopes, counts, outcomes and limitations; screen changed docs/state/deliverables and branch diff. Run native markdown_links on changed maintained Markdown only. Close pipe/clients, stop dedicated server with private-log pg_ctl wrapper and verify final status.

**Expected Result:** Public-safe implementation-evidence.md with separate real/synthetic counts and honest source/derivation status; required narrow checks passed; no live mutating commands/IPC/server before independent review.

#### Stop Conditions

- Wrong binding/worktree/branch/instance, manifest mismatch, unexpected schema/data, denied private write or loss of single-writer ownership: stop affected writes and report to Co; never recreate or reroute.
- Explicit truncation, invalid raw encoding, unrecognized response shape, ambiguous/missing embedded part or unsupported original retrieval: preserve available private evidence and classify incomplete; no successful full-import statement or cycle exit.
- Frame above the designed bound, timeout, namespace collision or unavailable current-user protection: reject safely; no unbounded retry or alternative data exposure. Any revised bound must preserve the exact source scope and safe host permissions.
- Byte mismatch, destructive source replacement, source growth on repeat import, overwritten correction, lost failure evidence or failed resume: stop completion and repair against the same approved invariants.
- Persistent reusable source code, additional dependencies or new app quality policy becomes necessary: return the admission/scope decision to Co before adding them; do not hide executable code in docs/runtime artifacts.
- Required applicable native check unavailable/failed, or private data detected in proposed commit: stop publication/review boundary and correct. No force transition.
- After two identical transient failures without new evidence, stop retrying and report the concrete cause; source safety and truthful status take precedence.
