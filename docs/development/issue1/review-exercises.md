## Walkthrough observations

| Scenario and concrete input | Source path followed | Observed instruction outcome / limit |
| --- | --- | --- |
| A1: Owner names Co, Imp and QA; Co assigns issue X at revision R in worktree A. | collaboration: modes, responsibilities, assignments; start and start-issue. | Recipient verifies original mandate plus actual instance/issue/branch; Co's setup/init interval ends before Imp receives sole mutation authority. Review is requested on a committed snapshot. No manual owner relay is required inside authorized routing. |
| A2: The owner already appointed QA; Imp delivers the review request. | collaboration: independent authority; QA role evidence precedence. | QA verifies the owner appointment and retains GO/NOGO authority. Sender identity alone does not downgrade it to preflight. Imp-created unappointed review remains findings-only. |
| A3: QA returns NOGO at R with a missing acceptance journey. | collaboration: verdicts and recovery; Imp/QA return paths. | Findings route to the producer, criteria remain unchanged, writer ownership resumes, repair produces R2, and QA reviews R2 before Co schedules progression. Co cannot rewrite NOGO. |
| A4: Co's local-product task discovers paid public hosting is needed. | collaboration: autonomous local product profile and original authority. | Local dependency installation is delegated to Imp; spending/public deployment is outside the default profile and becomes a concrete owner decision. Other safe work may continue. |
| A5: Imp is interrupted while a mutation-capable tool may still be running. | collaboration: single mutating Imp and resumption; host guide. | Co cannot grant a second writer merely because output stopped. It verifies termination, worktree/server/state and last valid verdict before releasing/reassigning. Unknown tool state blocks that worktree. |
| A6: Imp assigned to worktree B has only the parent's server bound to A. | collaboration: worktree isolation; host guide: instance admission. | B is not admitted. A separate dedicated instance/binding must be provisioned and demonstrated; a new directory or process label is insufficient. Parallel operation remains unproven until the live admission checks run. |
| A7: Chat return messaging is unavailable or lacks human authorization. | collaboration: mandate provenance and unavailable capability; host mapping. | No fabricated delivery/authority. Use another actually authorized role channel only if independence and routing are preserved; otherwise report the affected communication boundary to Co/owner. |
| A8: QA GO names R, but the producer changes a reviewed source to R2. | collaboration: exact revision verdict. | The affected GO is stale. Co must obtain a matching new review before progression; a broad old approval cannot cover a future revision. |
| A9: Imp launches a second writing subagent on another file in worktree A. | collaboration: single mutating Imp; Imp role. | Rejected by the procedural rule even though files do not overlap. Read-only support is possible; another writer needs a different admitted worktree or an explicit sequential ownership transfer. |
| A10: A new issue is ready after authorized closeout. | end-issue; go; phase override. | Interactive mode recommends/returns to owner. Coordinated mode dispatches only within the original issue/integration authority, with explicit IDs, valid verdicts and correctly routed instance; authority is not inferred from a producer message. |

These are observed paths through the written rules. They do not demonstrate tool delivery, actual permission enforcement, concurrent process exclusion or a live application.
