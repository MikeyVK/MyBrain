# Storage operations and publication contract

**Status:** Design candidate — review requested  
**Version:** 1.2  
**Last Updated:** 2026-10-28

## Purpose

Define the wire and transaction behavior of the registration boundary, including idempotency, branching, immutable reads and explicit partial outcomes.

## Summary

Commands prepare a durable intent, receive exact payloads, and publish one atomic registry change. Queries return a pinned publication basis and actual selected references. No successful acknowledgment precedes the corresponding durable effect.

## Common wire types and outcomes

HTTPS with authenticated owner sessions is required; no unauthenticated registry or retained-file endpoint exists. Transport framing is HTTP/1.1 or HTTP/2 with JSON UTF-8 envelopes. This contract chooses no HTTP framework or application language.

The model is normative for scalar/body types. Public BasisId is an immutable publication UUID; its internal ordinal is not an external version identity. Mutation, retry and cursor contexts also include current incarnation UUID, changed before a restored service reopens. A successful operation response is {operation_id:UUID,incarnation:UUID,state:committed,basis:BasisId,result:{created:ItemHead[],selected:ItemHead[],payloads:PayloadSummary[]}}. ItemHead={item_id,revision_id,selection_publication}; the last two are both required for CAS. ExactRef={item_id,revision_id}; ItemRef={item_id,revision_id:null}. One incarnation/operation_id identifies one immutable canonical request fingerprint.

Errors are closed objects {code:string,operation_id:UUIDOrNull,retryable:boolean,details:object}; details contain only authorized scope and no source plaintext. HTTP mapping:401 AUTH_REQUIRED/SESSION_REVOKED;403 OPERATION_NOT_AUTHORIZED;404 ITEM_NOT_FOUND/PAYLOAD_NOT_FOUND/HISTORICAL_BASIS_NOT_RESTORED;409 STALE_RELEASE_CONTEXT/HEAD_CONFLICT/IDEMPOTENCY_CONFLICT/STALE_RESTORE_CONTEXT/GRAPH_CONFLICT/DESTROYED_DEPENDENCY/PAYLOAD_ALREADY_READY/CURSOR_INVALID/SHARED_DEPENDENCY/STALE_DESTRUCTION_PLAN;410 HISTORICAL_DATA_DESTROYED;413 LIMIT_EXCEEDED;416 RANGE_NOT_SUPPORTED;422 INVALID_ENVELOPE/INVALID_PARENT/CONTRACT_NOT_ADMITTED/HASH_MISMATCH/LENGTH_MISMATCH/UNSUPPORTED_ERASURE_GUARANTEE/UNSUPPORTED_DESTRUCTION_SCOPE;500 INTERNAL_ERROR;503 INSUFFICIENT_STORAGE/DURABILITY_UNAVAILABLE/RECONCILIATION_REQUIRED. 202 with operation state prepared/receiving/ready/in_doubt is never successful publication. Network timeout is not proof of failure. Unexpected internal failures return stable INTERNAL_ERROR and retain protected diagnostics rather than claiming a completed effect.

## Command and query surfaces

All JSON command envelopes have schema_version="mybrain-storage/1", unknown core fields rejected. The model's recursive UTF-8/JSONB admission profile also applies to these envelopes before operation persistence; U+0000 is rejected as422 INVALID_ENVELOPE, while original bytes remain admissible through a valid PayloadPlan and binary upload. Each mutation requires the session and current incarnation. All record-body shapes are the closed typed contracts in the model; this table is normative for envelopes, not a second definition of those bodies.

Draft={item_id:UUID,role:Role,revision_id:UUID,parent_revision:UUIDOrNull,contract_revision:UUIDOrNull,body:RoleBody,mode:new_item/linear/branch}. UUIDs are generated by the registrar client library or service, never derived from hashes/provider IDs. New-item parent=null and exactly one selected head required. Linear parent must equal expected current selected head. Branch parent may be any existing revision of the same item, is stored without selection by default and may later be explicitly selected. Branch creation does not require that older parent to remain current. A batch can add at most one revision per item; more branches use separate idempotent operations.

HeadChange={item_id,new_revision,expected:{revision_id:UUIDOrNull,selection_publication:UUIDOrNull}}; both expected values null only for an absent new item. Selecting an existing older/branch revision still creates a fresh head-selection publication. HeadExpectation={revision_id:UUID,selection_publication:UUID}. CurrentDependency={item_id:UUID,expected:HeadExpectation}; it protects decisions based on a current view without forcing historically pinned inputs to be current. Every draft selected as linear must have a matching HeadChange; unselected branch drafts need none. Changing a component never silently advances its bindings: include explicit binding revisions/head changes for each intended subject.

PayloadPlan={payload_id,owner_item,byte_length:nonnegative decimal string,expected_sha256:HashOrNull,media_type:string,codec:stringOrNull}; owner may be an item created by this intent. Captured media is declared, not trusted proof of format. Inline limit 1 MiB, all larger payloads use retained files. A retry for an already ready payload returns its metadata only when supplied expected digest matches; otherwise409 PAYLOAD_ALREADY_READY rather than overwriting or claiming different submitted bytes were accepted. Query the operation after a lost upload response.

PayloadSummary={payload_id:UUID,owner_item:UUID,byte_length:decimalString,sha256:Hash,backend:inline/retained-file,custody:prepared/admitted}. Upload-ready means prepared, not published. RegisteredView={item:ItemHead,role:Role,basis:BasisId,view_contract_revision:UUID,composition_fingerprint:Hash,bindings:BindingSelection[],included:IncludedRevision[],custody:CustodyReport[],completeness:CompletenessReport,next_cursor:stringOrNull}. BindingSelection={binding:ExactRef,subject:ItemOrExactRef,slot:Slot,member:ExactRef,attached:boolean}; IncludedRevision={ref:ExactRef,role:Role,contract_revision:UUIDOrNull,body:RoleBody}. GET /v1/revisions/{revision} returns {revision:IncludedRevision,parent_revision:UUIDOrNull,publication:BasisId,body_hash:Hash}; canonical body bytes are reproducible under its pinned canonicalization contract, while original content is retrieved only through PayloadRef. CustodyReport={target:ExactRefOrPayloadRef,status:retained/reference_only/not_received/missing/corrupt/blocked,checked_at:UtcTimeOrNull,evidence:ExactRef[]}. CompletenessReport={scope:objectOrNull,status:established_complete/established_incomplete/unknown,assessment:ExactRefOrNull}; without an identified contract-qualified assessment it is unknown. A recorded assessment is attributed evidence, not proof of all external reality. SelectResponse={basis:BasisId,items:ItemHead[],next_cursor:stringOrNull}; cursors reuse the same selected basis. All responses pass current release control. An absent requested basis is explicit404 HISTORICAL_BASIS_NOT_RESTORED, never current fallback.

A persisted execution/input manifest is an ordinary role-manifest Draft in PUT /v1/operations/{id} and POST /commit, not a separate ambiguous alias endpoint. The command lists exact members actually selected/used. No read side effect creates a source.

Candidate-first example: operationA creates sourceS revisionR0 with content:null, and an ordinary pending lifecycle metadata set/binding. After commit, staging selectsS under its lifecycle-view contract; registration exists although no payload is promised. OperationB declares a large payload owned by existingS and a linear sourceR1 parentR0, uploads bytes, then CAS-selectsR1 and explicitly updates lifecycle bindings. Failure leavesS/R0 and its pending/failed descriptions; successful admission keepsS identity. If no candidate was requested, operation preparation is merely private command recovery, not a second candidate registration.

Predicate is {kind:item_role,value:Role}, {kind:metadata_contains,value:object,contract_revision:UUID}, or {kind:label_definition,definition:ExactRef,attached:boolean}. Metadata containment uses exact contract-qualified JSONB containment, not semantic inference; arrays retain JSONB containment semantics and callers must not treat that as ordered array equality. Full structural equality is {kind:metadata_equal,value:object,contract_revision:UUID}, compared against canonical JCS attributes. A missing property never equals explicit null. Label predicates select exact pinned definition revisions; no automatic definition migration. Arbitrary SQL, expressions, remote URLs and code are rejected. A cursor is an HMAC-SHA256 authenticated opaque token binding incarnation,basis,canonical query hash,last item_id,page_size and expiry(max 24h); altered/mismatched/expired tokens409 CURSOR_INVALID and never silently restart at current.

## Publication and idempotency

Prepare uses a unique NOT DEFERRABLE operation key. Concurrent preparation locks the operation row and compares canonical request SHA-256; do not use a one-statement INSERT DO NOTHING/SELECT CTE that assumes a conflicting row is visible in the same statement snapshot. A following statement after the conflict/row lock resolves the existing request. Stored request_body contains admitted pending revision descriptions and references, and is therefore a managed copy included in destruction/backup inventory. It is not a log. After commit remove duplicated pending descriptions from operation.request_body, retaining request fingerprint and an exact reference-only result; PG MVCC/WAL persistence remains part of the declared erasure limitations.

Publish is one PostgreSQL READ COMMITTED transaction. Acquire the shared maintenance/custody hold, then the global registry_clock row FOR UPDATE, then operation row, then affected item/head/dependency rows in UUID order. Re-read current heads after lock acquisition. Validate all expected revision+selection tokens, contract profiles and all referenced targets. Draft-only branches retain explicit parent ownership; linear selected drafts must parent the expected selected head. Existing immutable exact inputs need no current-head condition unless declared as CurrentDependency. Canonical validation failures roll back every registry write; no partial head update remains.

After all payload preparedness checks, allocate a new publication UUID and ordinal=last_ordinal+1 under the clock lock. Insert publication and typed revisions, edges/binding projections, head selections and current heads, promote prepared payload descriptors, set operation committed/result, and update clock in this SAME transaction. Use synchronous_commit=on and fsync=on. The publication lock is held until DB commit, so ordinals agree with commit visibility; no sequence value or wall clock proves publication order. Request bodies/results have bounded size; outside file/network I/O is never performed while holding this publication lock.

No FK alone proves body/edge consistency; the publisher's admitted validation plus controlled DB privileges enforce those invariants. A publisher crash after the database accepted commit but before a response leaves exactly one operation/publication. Resolve by the same operation key: committed response is replayed, in_doubt remains uncertain until actual query/reconciliation. A conflicting command must not silently create a new operation ID. Failed attempts preserve received payloads/evidence; retries require explicit resume, never automatic source deletion or blind external effects.

## Branching and reconstruction examples

If source S has selected R2, a caller may preserve R3 with parentR1 as mode branch without selecting it. A later select-existing HeadChange from expected(R2,C2) to R3 records selectionC3; historical selections remain. If the head later returns R2 underC4, a stale expected(R2,C2) conflicts despite the repeated revision ID.

For independent metadata changes on different binding items, both publications may succeed and the current view contains both; source content is not rewritten. Concurrent changes to the SAME binding or metadata-set head conflict by head token. The caller can re-read, deliberately merge/rebase, and submit a NEW operation; storage never chooses a semantic merge. Pinned relationships can form arbitrary semantic cycles; only parent/content-containment/derivation dependencies are required acyclic. Traversal limits apply to the requested selection/expansion, not the entire prior history.

A view coordinate (source,B) is not itself proof the composition changed: unrelated publications advanceB. The response also supplies composition_fingerprint=SHA256(JCS({item_revision,sorted attached binding/member exact refs,view_contract_revision})); B, request times and unrelated item heads are excluded. The hash includes ALL selected attached binding/member refs, independent of response include/projection, sorted by binding item UUID then revision UUID. The same actual selected combination has the same fingerprint under the core registered-view/1 contract, whose revision ID is returned in result metadata. The fingerprint is not source identity or a substitute for actual result-member records. Expand only declared include slots and explicit depth/limit; referenced identity profiles are not implicitly copied.

## Authorization and release linearization

### Owner session provisioning and control

Initial deployment supplies a locally generated 256-bit owner-control secret through protected provisioning and stores only its SHA-256 hash in owner_control(singleton=1,secret_hash bytea UNIQUE,generation bigint). An existing registry never auto-resets this key from a changed environment value. Loss requires an explicit offline owner recovery operation while release is disabled; no unauthenticated HTTP bootstrap endpoint exists.

POST /v1/sessions authenticates that control secret over HTTPS and accepts {expires_in_seconds:1..86400}; it returns {session_id,session_secret,expires_at,incarnation}. Validate the control hash/generation and insert the session while holding the owner_control row lock in ONE transaction, serialized with rotation; authentication before that lock is not sufficient. A session cannot be inserted using an old control secret after rotation commits. The random 256-bit session secret is returned once and only its hash is stored. This creates a global owner session, not another principal or entity entitlement. GET /v1/control/state authenticated by control secret returns {generation,incarnation}; it exposes no source data.

DELETE /v1/sessions/{id}, authenticated by owner-control secret, acquires the target session's exclusive lock, revokes it and returns {session_id,revoked_at}. Repeated revocation returns the existing revocation state. POST /v1/control/rotate authenticates the old control secret and accepts {expected_generation,new_control_secret}; the owner client generates the new 256-bit secret before submission. In one control transaction lock owner_control, CAS generation, store the new hash and revoke all sessions using exclusive session locks in UUID order. Return {generation}; if the response is lost, authentication with the already known new secret plus GET /control/state resolves success. Secret plaintext is excluded from operation intents, logs, diagnostics and backups; no server-side secret-return replay is required. Control requests use fixed core envelopes, not arbitrary source contracts.

Phase1 has one owner principal, with owner-authorized sessions rather than independent entity entitlements. The deployment admits a fixed owner identity; HTTPS bearer credentials are random 256-bit session secrets, hash-only at rest, expiry enforced, never in URLs/logs. Keys are base64url without padding encoding exactly 32 random bytes; generation, hashing and constant-time comparison are mandatory. Session table (session_id UUID PK,token_hash bytea UNIQUE,expires_at timestamptz,revoked_at timestamptz?,generation bigint) is control data, not source metadata. Tools receive only the owner's explicitly authorized session/operations. Phase2 bounded routes are not required to deploy phase1 and cannot bypass these checks.

All metadata, existence, query results and content leave through the owned release gate. Before creating a query snapshot, opening a payload descriptor, computing a response, consulting plaintext cache or prefetching ANY protected bytes, each request briefly takes the shared maintenance hold and captures ReadContext={incarnation:UUID,release_generation:decimalString} from CURRENT release_control. The hold may then be released for bounded preparation. All snapshots, buffers, descriptors and queued-but-unreleased units remain bound to that original context; it cannot be refreshed or relabeled within the request. Before EVERY release unit, under the shared maintenance hold and session lock, re-read CURRENT incarnation/generation as well as barriers/session state. A mismatch terminates the request as409 STALE_RELEASE_CONTEXT before headers, or aborts an already-started stream without releasing another protected unit. Discard unreleased plaintext, close descriptors and dispose the old snapshot; retries are new requests, never continuation with a new generation. Cache entries include incarnation/generation and cannot be retagged: a fresh request after destructive work uses a new snapshot/current existence lookup, not bytes or a result recovered from an old read context. Destruction and every barrier change permanently advance release_generation as specified in preservation, so removing a barrier never revalidates an old request. This globally invalidates even unrelated prefetched reads conservatively; it creates no entity rights. Acquire the SHARED maintenance/custody hold first, then the session shared lock, and read CURRENT barriers/session state using a separate READ COMMITTED control transaction. Historical query snapshots never supply the barrier check. Destruction installs barriers under the conflicting EXCLUSIVE maintenance hold, so checking a barrier and releasing a unit cannot race with its installation. A release unit is at most 64 KiB handed to the authenticated TLS transport. Prebuffer before locking; acquire session shared lock, verify unexpired/unrevoked generation and any destruction barrier, then perform the bounded transport write while holding it. No uncontrolled async producer may queue additional plaintext after lock release. A write deadline of 5s bounds lock occupancy; begin a unit only when at least that budget remains before session expiry, otherwise abort early, and cap the write deadline at expiry; on expiry/disconnect abort the stream, release lock and discard unreleased buffers. Reverse-proxy buffering/caching is disabled for protected responses; retained files have no separate public route.

Revocation acquires session exclusive lock, marks revoked and commits. Its effective point is that commit after prior release-unit locks finished. No later release-unit write may succeed under the revoked session; an already handed-off unit cannot be recalled even if its packets arrive later. Long-running reads re-check per unit and terminate on revocation. Session expiry has the same per-unit boundary. This implements the declared owned-route P30 boundary without claiming control over bytes already outside it, direct host-admin access or another application's native sessions. Native OpenCloud sessions are separately owner-controlled and never direct routes to the protected archive.

Current and historical queries use CURRENT authorization/destruction barriers; historical entitlement is not replayed. Storing a source contract grants no execution or disclosure authority. An external model/service receiving bytes is a disclosure and requires owner-delegated scope; no blanket publishing right is inferred. Session revocation is the explicit DELETE control operation above, authenticated by the separate owner-control secret; it has no entity-rights graph.

## Dependencies and evidence limits

PostgreSQL 18 core provides the selected transaction/constraint primitives; exact current patch/OCI digest and application/driver pins are deployment admission inputs, not guessed from this document. Required durable configuration and native proof obligations are in preservation/acceptance contracts. No application framework is needed to interpret the JSON/HTTP/SQL contracts.

Primary evidence: [transaction isolation and concurrent INSERT visibility](https://www.postgresql.org/docs/18/transaction-iso.html), [explicit locks](https://www.postgresql.org/docs/18/explicit-locking.html), [ON CONFLICT nondeferrable arbiter](https://www.postgresql.org/docs/18/sql-insert.html), [binary bytes](https://www.postgresql.org/docs/18/datatype-binary.html), [JSONB normalization](https://www.postgresql.org/docs/18/datatype-json.html). These document primitives, not an executed MyBrain implementation or performance result.
